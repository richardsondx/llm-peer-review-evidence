Research overview

Reviewer pilot: methods and limitations

Author: Richardson Dackam · Nshipyard · 1 October 2026. This is an exploratory text-only adaptation of SPOT, not an official SPOT replication.

Design and sample

27 unique manuscripts were selected by round-robin over five non-image annotation categories, in alphabetical title order within each category: equation/proof, statistical reporting, reagent identity, experiment setup and text–text inconsistencies. The sample contains 16 equation/proof papers, four statistical-reporting papers, three reagent-identity papers, two experiment-setup papers and two text–text inconsistency papers. This enriches it for equation/proof problems. The input is the repository’s normalized text, with each image replaced by an explicit omission marker. All selected-category annotations for each sampled paper are retained (29 total); other-category annotations are outside scope. There are 223 image omissions across the inputs.

These 27 manuscripts are distinct from the 27 studies in the literature audit. We do not claim to reproduce the experimental designs of those studies.

Execution amendment and supplementary runs

An initial CLI route completed 27 Luna reviews, but the Sol CLI requests were rejected before inference. The primary comparison was therefore moved to a consistent app sub-agent interface for both models, using fresh reviews. The earlier Luna CLI outputs and rejected Sol requests remain supplementary records and do not enter the paired primary scores. The change was recorded before any primary app reviews existed in the execution amendment.

Model execution

Requested runtime identifiers: gpt-6-luna and gpt-6.1-sol, both xhigh. Both primary runs use fresh app sub-agents with no inherited conversation per manuscript. The paper and schema can be read, and the output can be saved; browsing, annotations and other reviews are prohibited. Compliance is self-attested, not independently event-audited. Two manuscript reviewers can run concurrently within each model; Luna’s entire primary run precedes Sol’s. All receive the same fixed manuscript text, embedded reviewer prompt and JSON schema. Per-worker orchestration instructions specify paths and tool restrictions; public task templates document these instructions. Full app request envelopes are not independently audited. No annotations, peer outputs or source-audit results are supplied. These are app sub-agent measurements; runtime identifiers are selected in the spawn request, not independently attested API snapshot IDs. Tool restrictions and full-input reading are recorded as worker attestations.

Each manuscript receives one review per model. No regeneration is selected for higher scores. Failures and runs using prohibited tools are invalid, must remain documented, and cannot count as successful reviews.

Reference screening and scoring

The full annotation set remains visible. The primary denominator contains 12 references that describe a sufficiently specific error mechanism. Generic statements that a named theorem, table or experiment is flawed are excluded, as is the spelling-only reference outside the prompt’s substantive-error scope. Screening was saved after execution began, before eligible-case outputs were inspected; the P03 output had already been viewed to verify runtime behavior. This is not an external preregistration.

Each paper’s two outputs are assigned A/B labels with order determined by a hash of its case ID. A fresh GPT-6.1-Sol Extra High app sub-agent compares both to the references without reviewer model names. A match requires the same specific faulty mechanism and a compatible location. Generic criticism or shared topic is insufficient. The judge produces a short rationale and prediction indexes for each match. Scoring is automated and needs independent human validation; a Sol-family judge may introduce bias despite withheld model identities.

The headline reports matched specific annotations divided by the 12 eligible annotations. Broad reference matching is descriptive only. Neither reference matching nor a reviewer’s “established error” label verifies scientific truth. The annotations themselves may be incomplete or incorrect.

Measures intentionally unavailable

Without clean-paper controls and independent verification of every flag, we cannot estimate true precision, false-positive or hallucination rates. Without human reviewers or scoring tasks, we cannot measure human agreement, human-level performance or score bias. Self-reported confidence is displayed but is not confidence calibration. A failure to match a reference does not prove that the model found no valid scientific issue.

Reproducibility and rights

The manifest records paper identifiers, input SHA-256 hashes, source revision, text lengths and omitted-image counts. Raw reviewer JSON, run configuration, worker attestations, automated matching and screening rationales are downloadable. Full third-party manuscript text and private local runtime logs are excluded from publication; scripts rebuild inputs from the public SPOT repository. The annotation dataset is attributed to SPOT’s authors and SPOT-MetaData. Third-party material retains its own license.

The initial CLI execution protocol was saved before those reviewer outputs. The app execution amendment was saved before any primary app review outputs. The selection and scoring decisions are versioned in the repository; they are not a registered clinical or systematic-review protocol.
